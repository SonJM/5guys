# 사용 및 API 연결 가이드

## 달력과 자동 동기화

Google로 로그인하고 캘린더 권한에 동의하면 개인 일정이 DB에 적재됩니다. 달력 이동은 Google API를 직접 기다리지 않고 DB에서 해당 월을 조회합니다. 현재 월이 먼저 표시되고, 직전·다음 월은 백그라운드에서 미리 조회합니다. 데이터 절약 모드·느린 연결·숨겨진 화면에서는 미리 조회하지 않습니다.

이미 읽은 월은 해당 달력 컴포넌트의 브라우저 메모리에 최대 6개월분, 2분 유효기간으로 보관합니다. 유효기간이 지나도 기존 화면을 유지하면서 다시 조회합니다. 동일 월의 중복 요청을 합치며, 변경 없는 Google 동기화는 캐시를 무효화하지 않습니다. 변경이 있으면 캐시를 재조회하므로 일정 이동·삭제도 반영됩니다. 새로고침·컴포넌트 재생성 시 메모리 캐시는 사라집니다. 별도 Redis 서버는 필요하지 않습니다.

Google에서 수정한 내용은 웹훅/자동 동기화 → DB 반영 → 화면 갱신 순서입니다. 운영자는 [Realtime 마이그레이션](../supabase/migrations/202610120001_calendar_realtime.sql)을 Supabase SQL Editor에서 적용해야 DB 변경 알림이 열린 화면에 전달됩니다. 기존 본인 일정 조회 RLS를 유지하며, 그룹 구성원의 제목을 공개하지 않습니다. 적용하지 않아도 화면 사용 중 기존 2분 주기 동기화는 유지됩니다. 웹훅 지연·네트워크 단절이 있을 수 있어 즉시 반영이나 특정 초 이내 반영을 보장하지 않습니다.

## 주간·월간 근무표 사진

1. 근무 유형에 표기·별칭과 시간을 등록합니다. 예를 들어 사진의 `N`을 본인의 야간 근무 유형 별칭에 추가합니다.
2. 사진을 선택하면 전체 이미지가 자동 분석됩니다. 이름·월·잘라낼 영역을 미리 입력하지 않습니다.
3. 결과 달력에서 자동 연결된 근무와 날짜를 확인합니다. 주간·월간·임의 기간(최대 62일)을 지원하며 월말·연말을 넘는 날짜도 유지합니다.
4. 연도·날짜가 사진에 없거나 불명확하면 임의로 추정하지 않습니다. 결과의 **기간 수정**에서 첫날·마지막 날을 지정하고, **날짜 확인 필요** 항목은 선택해서 날짜를 보정합니다. 기간 안에서 같은 날짜·요일이 여러 번 나타나면 자동 연결하지 않습니다.
5. 유형이 연결되지 않거나 잘못 인식된 항목만 수정한 뒤 등록합니다. 기간 첫날을 옮기면 기존 날짜도 같은 간격으로 이동하므로 적용 후 확인합니다. 날짜가 없거나 기간 밖인 항목은 등록에서 제외됩니다.

분석은 OpenAI 이미지 입력을 사용합니다. Google Vision·DeepSeek 키는 필요하지 않습니다. 휴무는 바쁜 일정으로 저장하지 않고, 기존 근무를 삭제하지도 않습니다. 중복 날짜·이미 등록된 근무는 저장 전에 차단하며 기존 약속을 덮어쓰지 않습니다. 다인 근무표에서 본인을 구분할 수 없는 사진은 개인 표로 다시 올려야 합니다. 실제 사진마다 인식 오차가 있을 수 있어 최종 확인 단계는 유지합니다.

## 지도·길찾기는 어디까지 구현되어 있나요?

현재 **장소 검색과 이동시간 조회 코드는 구현되어 있습니다.** API 키를 설정해야 운영에서 호출할 수 있습니다. 반면 **앱 안에 지도 화면이나 경로 선을 그리는 기능은 아직 구현되지 않았습니다.** 키를 추가하는 것만으로 내장 지도가 생기지는 않습니다.

| 기능 | 현재 구현 | 필요한 서버 환경변수 |
| --- | --- | --- |
| 국내 장소·출발지 검색 | Kakao Local 키워드 검색으로 주소·좌표·장소 링크 조회 | `KAKAO_REST_API_KEY` |
| 자동차 이동시간 | Kakao Mobility 자동차 길찾기로 시간·거리 조회 | `KAKAO_MOBILITY_API_KEY` |
| 대중교통 이동시간·경로 요약 | ODsay 대중교통 길찾기 결과에서 최단 시간 경로 선택 | `ODSAY_API_KEY` |
| 추천 이유 | 실제 후보와 익명화된 이동시간을 바탕으로 설명, 실패 시 기본 결과 유지 | `OPENAI_API_KEY` (선택) |
| 장소 지도 열기 | 외부 지도/장소 링크로 이동 | 위 검색 키 |
| 앱 내 지도·경로 선 | 미구현, 별도 화면·SDK 연동 개발 필요 | 현재 JavaScript 지도 키는 사용하지 않음 |

현재 서버 구현은 [장소 API](../src/app/api/places/route.ts)에 있습니다. Kakao만으로 대중교통 경로를 처리하는 구조가 아니며 ODsay가 별도로 필요합니다. 약속 유형(카페·저녁·술·여행), 지역, 참여자별 출발지와 이동수단을 입력하면 최대 3개 후보와 최대 8명의 이동시간을 비교합니다. 출발지는 구체적인 역·장소명으로 입력하고, 검색된 이름이 맞는지 확인하세요. 조회 실패는 0분이 아니라 미확인으로 표시됩니다.

### Vercel 설정 순서

1. Kakao Developers 앱에서 REST API 키를 확인합니다. Local 사용에 필요한 서비스 설정·권한을 확인해 `KAKAO_REST_API_KEY`에 넣습니다.
2. Kakao Mobility Developers의 길찾기 서비스 등록과 사용 권한을 확인한 REST API 키를 `KAKAO_MOBILITY_API_KEY`에 넣습니다. 환경변수 이름은 구분했지만, 동일 앱 키가 양쪽 서비스에서 허용된다면 같은 값을 사용할 수 있습니다. JavaScript 키·OAuth 클라이언트 비밀키를 대신 넣지 않습니다. 등록 절차는 [Kakao Mobility 시작 가이드](https://developers.kakaomobility.com/guide/navi-api/start)를 확인하세요.
3. ODsay에서 대중교통 길찾기 API 키를 발급하고 서버 호출에 맞는 인증·접근 제한과 사용량을 확인한 뒤 `ODSAY_API_KEY`에 넣습니다. Vercel 서버 호출이 허용되는 설정인지 서비스 제공자 기준으로 점검하세요. 고정 IP가 있다고 가정하지 않습니다.
4. Vercel 프로젝트 → Settings → Environment Variables에서 위 값을 **Production**에 추가하고 재배포합니다. Preview에서도 테스트하려면 해당 환경에도 별도로 설정합니다. 모두 서버 비밀키이며 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.
5. 로그인 후 장소 추천에서 자동차·대중교통을 각각 실제 조회해 봅니다. 연결 상태는 키의 존재 여부만 확인합니다. 값이 있어도 권한·할당량·서비스 등록 문제로 실호출은 실패할 수 있습니다. Google 로그인/Calendar 권한과는 별도 설정입니다.

키 설정만으로 모든 기능이 무료가 되는 것은 아닙니다. 제공자별 현재 요금·쿼터·가입 조건을 확인하세요. Kakao Local의 실제 검색 요청과 응답은 [공식 Local API 문서](https://developers.kakao.com/docs/en/local/dev-guide), 대중교통 요청은 [ODsay 개발 가이드](https://lab.odsay.com/guide/guide?platform=web)를 참고하세요.

### 현재 제한

- 자동차·대중교통 시간은 조회 시점의 참고값입니다. 미래 약속 시각의 교통·막차, 영업시간·예약 가능성을 보장하지 않습니다.
- 시외 ODsay 결과의 터미널/역 사이 구간에 출발지→터미널, 터미널→최종 목적지 구간을 추가 연결하는 처리는 아직 없습니다. 국내 장거리 여행에서 전체 문전 이동시간으로 해석하면 안 됩니다.
- 여행 추천은 관광명소 후보 비교이며 숙박·다일 여정 최적화가 아닙니다.
- 실제 운영 API 키와 이미지·로그인 세션으로 확인하지 않은 기능은 코드·모의 응답 검증만으로 정상 연결을 보장할 수 없습니다.
