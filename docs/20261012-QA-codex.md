### P2 · QA-10 일정은 보이는데 ‘연결 복구’가 필요한 이유를 이해하기 어려움

**사용자 질문:** “로그인도 했고 일정도 보이는데, 무엇이 연결되지 않았다는 거지? 친구와 시간을 맞춰도 되는 상태인가?”

- **관찰：** 로그인된 내 일정·그룹·장소 화면에 같은 연결 경고가 반복됩니다. 화면에는 최종 동기화 시각, 현재 이용 가능한 기능, 연동 복구 전 데이터의 신뢰 수준이 표시되지 않습니다. 실제 실시간 동기화 장애 여부는 별도 조사 항목입니다.
- **개선：** 로그인 상태와 Calendar 연결 상태를 구분하고, 상태 옆에 영향과 다음 행동을 짧게 표시하세요. 처음 사용한다면 ‘캘린더 연결 → 내 일정 확인 → 그룹 만들기’ 같은 최소 시작 순서를 제공하세요. 권한 요청 시 읽기·수정 권한이 각각 필요한 이유도 알려주세요.
- **완료 기준：** 사용자가 경고만 보고도 지금 가능한 작업과 복구가 필요한 작업을 구분할 수 있고, 그룹의 가능 시간에도 데이터 갱신 상태를 확인할 수 있음.

### P2 · QA-11 처음 온 친구를 데려오는 초대 동선이 부족함

**사용자 질문:** “친구에게 무엇을 보내야 하지? 아직 가입 안 한 친구는 어떻게 초대하지?”

- **관찰：** 그룹 초대 UI는 ‘기존 사용자’ 선택창과 초대 버튼입니다. 현재 계정에서는 선택 가능한 사용자가 없고, 이메일·초대 링크·초대 코드 입력이나 빈 목록에 대한 다음 행동 안내도 찾지 못했습니다. 테스트 사용자 제한이 목록에 영향을 줄 수 있으므로, 초대 서버가 고장났다고 판단한 항목은 아닙니다.
- **개선：** 친구에게 전달할 수 있는 초대 링크/코드 또는 이메일 초대 동선을 제공하고, 가입 후 원래 그룹으로 돌아오게 하세요. 제한된 베타를 유지한다면 가입 가능한 대상과 테스트 사용자 추가 방법을 먼저 알려주세요. 선택 가능한 대상이 없을 때 이유를 표시하고 초대 버튼을 비활성화하세요.
- **완료 기준：** 새 친구가 필요한 조건을 이해하고 초대받은 그룹에 도달하는 한 경로가 명확히 제공됨. 이번에는 다른 사람에게 초대를 보내지 않았음.

### P3 · QA-12 모바일에서 같은 그룹을 고르는 선택창이 두 번 나옴

**사용자 질문:** “위에서 고른 그룹과 아래 ‘내 그룹’은 다른 건가? 어디를 바꿔야 하지?”

- **관찰：** 모바일 ‘그룹 → 멤버 관리’에 상단 ‘그룹 선택’과 본문 ‘내 그룹’ 선택창이 동시에 나타나며 같은 QA 그룹을 표시합니다.
- **개선：** 활성 그룹 선택은 한곳으로 통합하고, 나머지 영역에는 선택된 그룹 이름을 읽기 전용 제목으로 보여주세요. 현재 구성원·초대·설정이 이 그룹에 적용된다는 연결도 명확히 하세요.
- **완료 기준：** 그룹을 선택하는 인터랙션은 한 번이며, 관련 정보와 작업 대상이 일관되게 표시됨. 그룹 간 상태 불일치는 여러 그룹을 만들지 않아 검증하지 않았음.

### P2 · QA-13 · 직접 재현 멤버를 확인하러 다녀오면 그룹 계획 초안이 사라짐

**사용자 질문:** “누구랑 가는지 확인하고 왔을 뿐인데, 방금 쓴 여행 이름은 어디 갔지?”

### P2 · QA-14 일정을 확인하려고 눌렀는데 날짜가 바뀌고 수정 화면이 열림

**사용자 질문:** “오늘 일정을 보려던 건데 왜 다른 날짜가 선택됐지? 보기만 하려는데 저장·삭제가 먼저 보이네.”

- **관찰：** 10월 12일 목록에 표시된 여러 날짜에 걸친 일정을 누르자, 달력 선택과 폼 제목이 원래 시작일인 10월 7일로 바뀌고 즉시 ‘일정 수정’ 폼이 열렸습니다. 저장·삭제·취소가 제공되며 별도의 읽기 전용 상세 단계는 없었습니다.
- **개선：** 먼저 읽기 전용 상세에서 전체 시작·종료 날짜, 종일 여부, 일정 출처를 보여주고 ‘수정’을 별도 행동으로 분리하세요. 조회하던 날짜는 유지하거나 시작일로 이동하는 이유를 설명하세요.
- **완료 기준：** 여러 날짜에 걸친 일정을 열어도 사용자가 조회 중인 날짜를 놓치지 않고, 편집 여부를 스스로 선택할 수 있음.

### P2 · QA-15 개인 일정의 날짜 이동·종일·긴 기간을 표현하기 어려움

**사용자 질문:** “약속을 다음 주로 옮기고 싶은데 날짜 입력이 없네. 이틀 넘는 일정은 어떻게 넣지?”

- **관찰：** 개인 일정 추가·수정 폼에는 제목, 시작·종료 시각, ‘다음 날 종료’가 있습니다. 날짜는 폼 제목에 표시되며 편집할 날짜 입력, 종일 선택, 임의 종료 날짜 컨트롤을 찾지 못했습니다. 새 일정에는 반복 선택이 있지만 관찰한 기존 일정 수정에서는 보이지 않았습니다.
- **개선：** 시작·종료 날짜와 시간, 종일 옵션을 제공하고, 일반 당일 입력은 간단하게 유지하세요. 반복 일정은 해당 일정만 변경하는지 전체를 변경하는지도 드러내세요. 목록에서 ‘+1일’만 표시하기보다 전체 날짜 범위를 읽을 수 있게 하세요.
- **완료 기준：** 기존 일정을 다른 날짜로 이동하거나 2일 이상 기간을 입력할 때 삭제·재생성에 의존하지 않음. 실제 일정 저장과 반복 수정은 이번 점검에서 하지 않았음.

### P3 · QA-16 여러 달을 둘러본 후 오늘로 돌아오는 지름길이 없음

**사용자 질문:** “몇 달 뒤를 봤는데 오늘로 돌아가려면 이전 달을 계속 눌러야 하나?”

- **관찰：** 내 일정·그룹 달력에는 이전/다음 달 버튼이 있고, 월 제목은 텍스트입니다. ‘오늘’ 또는 월·연도 바로 선택 컨트롤은 확인되지 않았습니다. 월을 넘기면 선택일이 새 달의 첫날로 바뀌었습니다.
- **개선：** ‘오늘’ 버튼과 월·연도 선택을 제공하고, 이동 후 선택 날짜 정책을 일관되게 하세요. 작은 화면에서는 현재 날짜와 선택 날짜를 구분해 표시하세요.
- **완료 기준：** 몇 달을 이동한 뒤 한 번의 행동으로 오늘 또는 원하는 월로 갈 수 있음.

### P2 · QA-17 여행을 계획하는데 사용자가 시간을 계산해야 함

**사용자 질문:** “여행 2일을 48시간으로 바꿔 넣어야 하나? 여행을 선택했는데 기본 시간은 두 시간 그대로네.”

- **관찰：** 공통 시간 검색은 ‘약속 길이(시간)’ 입력으로 통일되어 있으며 ‘여행 2일은 48시간’ 안내가 있습니다. 날짜 후보의 계획 유형을 ‘여행’으로 바꿔도 시작·종료는 같은 날 18:00–20:00으로 유지됐습니다.
- **개선：** 약속은 시간, 여행은 출발·복귀 날짜/시간 또는 일·박 단위로 입력하게 하세요. 계획 유형에 맞는 예시와 기본값을 제공하고 검색 길이와 제안 기간을 함께 확인할 수 있게 하세요. 이미 수정한 값은 일방적으로 덮어쓰지 마세요.
- **완료 기준：** 사용자가 일수를 시간으로 환산하지 않고 원하는 여행 기간을 설정할 수 있으며, 설정된 검색 길이와 실제 후보 기간이 명확함.

### P3 · QA-18 검색 조건과 구성원 시간표가 한 접기 영역에 섞여 있음

**사용자 질문:** “검색 기간을 바꾸려는데 왜 구성원 시간표까지 열리지? 첫 번째 날짜는 무엇의 시작일이지?”

- **관찰：** ‘기간·약속 길이 조정 및 구성원별 시간표’ 한 영역에 날짜·기간·길이·시간표가 들어갑니다. 첫 날짜는 접근성 이름 ‘약속 날짜’는 있지만 화면상 별도 시작일 라벨이 없고, 두 번째 날짜에는 ‘검색 종료일’이 표시됩니다. 390px에서 시간표는 약 307px 영역 안의 760px 표로 가로 스크롤됩니다.
- **개선：** ‘검색 조건’과 ‘구성원 시간표’를 분리하고 첫 날짜를 ‘검색 시작일’로 표시하세요. 적용 중인 날짜 범위·길이를 접힌 상태에서도 요약하고, 표에는 좌우로 이동할 수 있다는 단서를 주세요.
- **완료 기준：** 사용자가 일정 날짜, 검색 시작일, 검색 종료일을 구분하고 필요한 조정만 열 수 있음.

### P2 · QA-19 시간을 맞춘 다음 장소를 찾을 때 계획 맥락이 이어지지 않음

### P3 · QA-22 사진은 분석됐는데 파일 선택에는 ‘선택된 파일 없음’이 보임

- **개선：** 업로드한 파일 이름·썸네일과 ‘분석 완료’ 상태를 별도로 표시하고 버튼을 ‘사진 바꾸기’로 전환하세요. 같은 파일을 다시 고르기 위해 입력을 초기화하더라도 사용자용 상태는 유지하세요.
- **완료 기준：** 분석 결과가 보이는 상태에서 사용자가 업로드 실패로 오해하지 않음.

### P3 · QA-23 로딩 중에 ‘없음’이라는 결과를 먼저 보여줌

**사용자 질문:** “등록한 근무 유형이 없어졌나? 잠깐 뒤에는 왜 하나가 나오지?”

- **관찰：** 근무 유형 설정에 들어가자 처음에는 ‘등록된 근무 유형 0 / 아직 등록된 근무 유형이 없어요’가 나오고, 조회 완료 후 기존 주간 유형 1개로 바뀌었습니다. 그룹 달력도 가능 시간을 불러오는 동안 추천 0과 결과 없음 안내가 함께 표시됐습니다.
- **개선：** 로딩·성공 결과·진짜 빈 상태·오류를 분리하세요. 이전 데이터를 유지하며 갱신 표시를 하거나 스켈레톤을 보여주고, 조회 완료 전에는 단정적인 결과 없음 문구를 표시하지 마세요.
- **완료 기준：** 느린 응답에서도 ‘삭제됨/결과 없음’으로 오해할 수 있는 중간 상태를 보여주지 않음.

### P3 · QA-24 근무 유형 설정에서 사용자가 알아야 하는 개념이 많음

**사용자 질문:** “근무 이름과 OCR 별칭이 어떻게 다르지? 야간과 휴무를 하나씩 직접 설정해야 하나?”

- **개선：** 주간/저녁/야간/휴무 예시 템플릿을 시작점으로 제공하고 실제 회사 시간으로 수정하게 하세요. ‘앱에서 보여줄 이름’과 ‘사진에서 읽힐 표기’ 차이를 설명하고 야간·휴무의 처리 예시와 지속적인 라벨을 제공하세요.
- **완료 기준：** 처음 보는 사용자도 자기 표의 D/E/N/휴무를 어떤 필드에 넣는지 알 수 있고, 시간 기본값을 자기 근무에 맞게 확인할 수 있음.

### P3 · QA-25 공통 시간이 없을 때 사용자가 다음 날짜를 직접 찾아야 함

**사용자 질문:** “안 되는 건 알겠는데 그래서 가장 빨리 가능한 날이 언제야?”

- **관찰：** 선택 날짜의 공통 시간 없음 안내와 검색 범위의 시간 없음 안내가 따로 표시됩니다. 기본 검색 범위는 선택한 하루이고, 기간을 늘리는 컨트롤은 접힌 영역 안에 있습니다. 현재 그룹에서는 10월 12일에는 0시간, 17일에는 24시간 가능으로 표시되지만 가까운 가능 날짜로 이동하는 동선은 찾지 못했습니다.
- **개선：** ‘다음 가능한 날 찾기’, ‘이번 주 전체 보기’, ‘길이 줄이기’ 같은 직접 행동을 제안하세요. 상태 안내를 중복하기보다 어떤 조건을 바꾸면 되는지 보여주고, 다른 사람의 일정 제목을 노출하지 않는 범위에서 설명하세요.
- **완료 기준：** 결과가 없을 때 달력을 수동으로 탐색하지 않고 한 번의 행동으로 의미 있는 대안 검색을 시작할 수 있음.

### P2 · QA-26 장소 추천 실패 후 가능한 다음 행동이 없음

**사용자 질문:** “검색 연결이 준비되지 않았다는 건 내 잘못인가? 계속 눌러야 하나, 다른 방법이 있나?”

- **완료 기준：** 실패했을 때 무엇을 바꿔야 하는지 또는 지금은 이용할 수 없는지 판단할 수 있고, 같은 입력을 반복하게 만들지 않음.

### 유지할 만한 경험과 이번 재점검의 차이

개인 일정 초안은 메뉴를 이동한 후 다시 열어도 유지됐습니다. 다른 작성 폼도 이 경험에 맞추는 것이 좋습니다. 같은 가상 근무표를 10월 12일 다시 분석했을 때는 ‘주간’ 1건만 확인 대상으로 표시되어, 1차 QA에서 지적한 휴무 30개 카드의 긴 목록은 이번 샘플에서 재현되지 않았습니다. 실제 근무표·다인 그룹·저장 결과에 대한 일반화는 하지 않았습니다.

이번 추가 점검은 화면 이동과 저장하지 않은 테스트 입력, 승인된 가상 이미지 업로드로 진행했습니다. 새 그룹·실제 일정·초대·의견을 추가하지 않았고 기존 계정 설정을 저장하지 않았습니다. 앞서 만든 QA 그룹은 관리 UI에서 삭제 기능을 찾지 못한 상태로 계속 남아 있습니다.

### P2 · QA-03 달력 선택 날짜와 날짜 후보 폼 기본값 불일치

### P2 · QA-04 그룹 관리 기능과 생성 후 정리 동선 부족

- **환경：** 본인이 생성한 QA 그룹, 데스크탑·모바일 관리 화면.
- **실제：** 그룹 생성·선택·초대 컨트롤은 있지만, 그룹 삭제·이름 변경·현재 멤버 목록을 관리하는 컨트롤을 찾지 못함. 모바일 탭 이름은 ‘멤버 관리’인데 현재 멤버 목록도 표시되지 않음.
- **영향：** 실수로 만든 그룹을 사용자가 UI에서 정리할 수 없으며, 이번 QA 그룹도 남아 있음.
- **개선：** 소유자에게 그룹 설정·이름 변경·삭제 동선을 제공하고, 구성원 목록·역할·그룹 나가기 동선을 구분. 삭제 영향과 확인 단계를 명확히 표시.

### P3 · QA-05 모바일 하단 메뉴에 시각적 텍스트 라벨 없음

내 일정·그룹·장소 추천·더보기는 접근성 이름은 있지만 화면에는 아이콘만 표시됩니다. 첫 방문자가 메뉴 의미를 추측해야 합니다. 아이콘 아래 짧은 라벨을 추가하고 선택 상태를 유지하는 편이 좋습니다.

재현: 모바일 대시보드 하단 메뉴 확인. 증거: [모바일 그룹 화면](qa-mobile-group-empty.jpg).

### P3 · QA-06 그룹 빈 상태의 다음 행동이 불명확

그룹이 없을 때 “먼저 그룹 메뉴에서 새 그룹을 만들거나 참여해 주세요”라고 안내하지만, 모바일에서는 이미 ‘그룹’ 메뉴 안에 있고 실제 생성 화면은 ‘멤버 관리’ 탭입니다. 안내 문구를 실제 컨트롤 이름과 일치시키고 ‘첫 그룹 만들기’ 버튼으로 바로 연결하세요. 초대 버튼이 비활성화된 이유도 해당 화면에서 알려주는 것이 좋습니다.

재현: 그룹이 없는 계정 → 모바일 ‘그룹’. 증거: [생성 전 빈 상태](qa-mobile-group-empty.jpg).

### P3 · QA-07 추천 시간 목록이 너무 길고 자정부터 시작

일정이 없는 10월 17일, 2시간 조건에서 30분 간격 후보 45개가 표시됩니다. 계산상 올바른 수이지만 첫 후보는 00:00–02:00이고 같은 날짜가 카드마다 반복됩니다. 모바일에서는 계획 제안 폼까지 긴 목록을 지나야 합니다.

허용 시간대·선호 시간·정렬을 사용자가 선택하게 하고, 날짜는 묶어 표시하며 우선 후보와 전체 목록을 나누세요. 교대 근무자를 위한 서비스이므로 야간 시간을 일괄 제외하기보다 사용자 선호를 반영하는 방식이 적합합니다.

증거: [320px 화면의 추천 후보 목록](qa-mobile-recommendations-320.jpg).

### P3 · QA-08 OCR 확인 화면에서 제외 대상까지 긴 카드 목록으로 표시

**10월 12일 부분 개선 확인:** 같은 가상 근무표의 확인 대상은 주간 1건만 표시됐고, 휴무 30개 카드의 긴 목록은 이번 샘플에서 재현되지 않았습니다. 아래는 10월 8일 관찰 기록입니다. 선택 0개에서도 등록 버튼이 활성인 동작은 다시 관찰했으며, 실제 등록 처리는 테스트하지 않았습니다.

가상 근무표의 31개 날짜를 정확히 인식했지만, 등록된 근무 유형이 ‘주간’ 하나인 테스트 계정에서는 ‘휴무’ 30개도 각각 선택 불가능한 체크박스와 근무 유형 선택 카드로 표시됩니다. 한 개의 등록 가능한 일정을 확인하려면 불필요한 목록을 많이 스크롤해야 합니다.

휴무·등록 제외 항목을 요약하거나 필터로 접고, ‘인식 31 / 등록 후보 1 / 제외 30’처럼 수량과 이유를 보여주세요. 선택 0개에서도 ‘확인한 일정 등록’ 버튼은 활성 상태이므로 선택 조건을 안내하거나 비활성화하는 것도 개선 후보입니다. 버튼을 누르지는 않았으므로 실제 0개 등록 처리 동작은 미검증입니다.

증거: [OCR 결과 화면](qa-mobile-ocr-result.jpg) · [사용한 가상 근무표](qa-test-work-calendar.png).

### P3 · QA-09 모바일 문장의 단어 중간 줄바꿈

로그인 전 390px 첫 화면의 사용 안내 제목에서 ‘가벼워집니다’가 ‘가벼워 / 집니다’로, 320px 근무 설정 제목에서는 ‘시간’이 ‘시 / 간’으로 나뉘는 모습을 관찰했습니다. 한국어 단어 단위 줄바꿈과 좁은 화면의 제목 크기·여백을 조정하세요. 긴 입력값에는 별도 넘침 처리를 적용해 가로 스크롤을 만들지 않도록 확인해야 합니다.

## 추가 조사가 필요한 관찰

### 로그인 후에도 Calendar 연결 복구 경고 지속

로그인된 대시보드와 그룹·장소 화면에 “일정 자동 업데이트 연결이 필요해요”가 계속 표시됐습니다. 기존 일정 읽기는 동작했으나 실시간 동기화·일정 쓰기까지 정상이라는 뜻은 아닙니다. 권한 동의 여부, 캘린더 연동 상태, 토큰 보관·갱신 과정을 확인해야 합니다. 이번에는 캘린더를 수정하거나 복구 동의를 다시 진행하지 않아 원인과 동기화 장애를 확정하지 않았습니다.

로그인 전 Google 인증 화면에서는 ‘5총사’ 대신 Supabase 프로젝트 주소가 서비스 이름처럼 표시돼 서비스 신뢰감도 떨어질 수 있습니다. OAuth의 사용자 표시 이름·브랜딩을 확인하세요. 로그인 자체는 최종적으로 성공했습니다.

### 검증하지 않은 부분

실제 휴대폰의 Safari·Chrome, 터치·가상 키보드·안전 영역, 여러 계정의 공통 시간 교집합과 권한 분리, 다른 사람 초대, 개인 일정 저장·수정·삭제·반복 일정, 그룹 계획 등록·확정·의견, Google Calendar 실시간 변경 반영, 실제 촬영 사진 및 다양한 파일 형식 OCR, 다크 모드 변경은 검증하지 않았습니다. 모바일 결과는 브라우저 화면 크기 테스트 기준입니다.

그룹 생성 외 서비스의 기존 데이터를 수정하지 않았습니다. 업로드한 이미지는 개인정보가 없는 가상 데이터입니다. 브라우저 도구의 실행·캡처 오류는 서비스 결함으로 분류하지 않았습니다.

보고서와 증거 화면은 로컬 파일입니다. 이미지 링크를 누르면 원본 증거를 확인할 수 있습니다. 이번 결과는 관찰한 배포본과 테스트 계정 상태에 한정됩니다.
