# 2026-10-12 QA 검토와 수정·설계 결과

대상: `20261012-QA-codex.md`, 현재 저장소 코드, 직전 대화에서 승인한 사진 분석 UX 변경.

## 검토 후 진행할 설계

### A. 새 친구 초대와 그룹 관리 (QA-04·11)

추천 정책: 생성자가 발급한 7일 유효 초대 링크로 로그인한 친구가 그룹 이름을 확인하고 명시적으로 참여한다. 링크는 여러 친구에게 공유할 수 있고 생성자가 언제든 폐기한다. 기존 Google 로그인과 콜백을 사용하며 로그인 후 초대 화면으로 돌아온다. Google 테스트 앱에서 접근 불가능한 계정은 앱 초대와 별도로 Google 테스트 사용자 등록이 필요하다.

`group_invites`에는 원문 토큰 대신 해시, 그룹, 발급자, 만료·폐기 시각을 저장한다. 토큰 조회는 최소 그룹 이름만 반환한다. 참여 RPC에서 로그인·만료·폐기·그룹 인원(20명)·기존 멤버 여부를 한 트랜잭션으로 검증한다. URL의 임의 그룹 번호만으로 참여할 수 없게 한다.

그룹명 변경·초대 폐기는 생성자만 한다. 일반 구성원은 나갈 수 있고, 생성자는 소유권 이전 또는 그룹 정리 후에 나간다. 삭제는 30일 복구 가능한 그룹 보관 처리로 제안한다. 그룹 계획과 구성원 접근만 숨기며 개인 일정과 외부 캘린더 일정을 삭제하지 않는다. QA 테스트 그룹 정리는 이 UI가 생긴 뒤 생성자가 선택해서 진행한다.

검토할 결정: 링크를 가진 로그인 사용자에게 즉시 참여를 허용할지, 생성자 승인을 한 번 더 받을지. 추천은 친구 서비스의 흐름에 맞는 '참여 버튼으로 바로 가입'이다.

### B. 개인 일정 날짜·종일·여러 날·반복 편집 (QA-15)

추천 정책: 시작·종료 날짜와 시간을 분리하고 종일 선택 시 시간 입력을 접는다. 종일의 UI 종료 날짜는 마지막 포함 날짜로 표시하되 DB·외부 캘린더의 종료 값은 다음 날 00:00(미포함)으로 변환한다. 시간 일정은 실제 시작·종료 순간을 저장한다. 현재 한국 시간 기준을 유지한다.

앱에서 생성한 반복 일정은 이번만/이후/전체 범위를 유지하며 날짜 이동량과 기간을 각 발생 일정에 적용한다. 업데이트는 한 트랜잭션으로 검증·반영하고, 한 항목 실패 시 전체 적용을 취소한다. Google에서 가져온 반복 일정은 현재 개별 발생으로 적재하므로 우선 해당 발생만 수정한다. 원본 반복 규칙 편집은 별도 확장으로 둔다.

검토할 결정: 위와 같이 앱 반복과 외부 반복을 구분한 초기 범위를 승인할지. 추천은 이 범위부터 구현하는 것이다.

### C. 여행 기간과 장소 참여자 연계 (QA-17·19)

추천 정책: 여행은 출발·복귀 날짜/시간으로 입력하고 '1박 2일 · 실제 33시간'처럼 계산 결과를 함께 표시한다. '2일'을 무조건 48시간으로 해석하지 않는다. 신규 기본값은 선택일 09:00 출발, 다음 날 18:00 복귀를 예시로 제시하되 이미 수정한 값은 보존한다. '이 기간으로 공통 시간 찾기'로 실제 기간을 검색 조건에 적용하고 30분 단위 계산과 맞춘다.

특정 계획에서 장소 찾기로 이동하면 계획·그룹·유형·기간을 전달한다. 그룹 전체를 무조건 참여자로 확정하지 않고 구성원 이름을 선택 목록으로 제공한다. 현재 경로 비교 한도는 8명이고 8명을 넘으면 대상 선택을 요청한다. 출발지는 저장하지 않는다. 조회 시점 경로는 미래 출발시각의 운행을 보장하지 않는다는 현재 안내를 유지한다.

검토할 결정: 여행을 실제 출발·복귀 기간으로 검색하고 참여자는 그룹 구성원 중 선택하는 방향을 승인할지.

### D. 일정 갱신 상태와 운영 설정 (QA-01·10·26)

정상 상태에서 별도의 Google Calendar 카드를 만들지 않는다. 그룹 가능 시간 RPC에 일정 제목 없이 갱신 시각·갱신 오류 여부만 추가해 계산 결과 옆에 간단히 표시하는 방향을 제안한다. 갱신 시각이 오래됐다고 이미 저장된 일정 자체를 무효화하거나 사용자를 '가능'으로 새로 추정하지 않는다.

운영 확인은 Vercel Production의 `KAKAO_REST_API_KEY`, `KAKAO_MOBILITY_API_KEY`, `ODSAY_API_KEY` 설정과 실제 호출, 동기화 연결의 last_error·갱신 토큰·OAuth 동의 확인이다. 값은 문서·로그에 기록하지 않는다. Google OAuth 사용자 표시 이름과 테스트 사용자 제한은 콘솔 설정이다.

## 검증 범위

로컬 테스트 21개(단위·DB/RLS), 타입 검사, 린트, 프로덕션 빌드가 통과했다. 사진 분석 재매핑 시 수동 제외를 보존하는 회귀 검사를 추가했다. 빌드는 테스트용 공개 Supabase 설정으로 진행했다. 운영 로그인 세션·실제 휴대폰·외부 API 키의 유효성은 이 환경에서 검증하지 않았다. 보고서의 QA 그룹과 운영 일정은 수정하지 않았다.
